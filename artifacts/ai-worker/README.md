# Nimbus private AI endpoint

Firebase Hosting stays on Spark. This native Cloudflare Worker runs on Workers Free; no Firebase Functions or billing changes are needed. The browser sends a Firebase ID token, and the Worker verifies the signature and Nimbus audience before calling the selected assistant.

The corner Nimbus bubble opens Task AI. Switching to General AI opens a fullscreen glass view over the current page; minimizing preserves the draft and conversation, and reopening restores that mode. Legacy `/general` links open this same overlay.

General AI uses Groq's preview `qwen/qwen3.8-27b`, with a focused writing/review/code/vision harness in `src/generalHarness.mjs`. Strict reviews retain three passes (draft, evidence audit, final editor); writing and basic code use two. General questions and images use one pass; image prompts include explicit baseline/ratio checks instead of transmitting the same image twice. Each pass is capped at 900 completion tokens on Groq. Ordinary questions omit essay-specific reliability instructions. Up to two measured word-count repairs and one ambiguous-person-reference repair remain available when needed; answers are never mechanically truncated. The Markdown-aware ambiguity guard rejects corrections that guess an unidentified speaker or owner. These changes reduce free-tier use but do not remove provider quotas or prove the complete quality target.

Groq Qwen's published free limits include 8,000 tokens/minute and 200,000 tokens/day, shared across the organization ([official limits](https://console.groq.com/docs/rate-limits)). Two reviews previously used about 8,100 tokens and triggered a minute-level 429. Short cooldowns of up to 60 seconds may be retried once if the 85-second request budget permits. A daily-limit rejection is never automatically retried; the public error distinguishes daily exhaustion from a timed cooldown and never exposes the upstream account ID or credential. A controlled two-short-texts-then-chart sequence now completed with three calls and 3,686 total tokens. Other workloads and simultaneous users can still hit the shared quota. Heavy qualification runs use the same allowance as the live site and should not consume the user's daily capacity.

Task AI still uses Groq `openai/gpt-oss-20b`, low reasoning and strict structured previews. Simple dates, scheduling shortforms and projects use the deterministic parser first. General requests receive no workspace data, and Task previews require user confirmation. General accepts one PNG/JPEG/WebP image per message, resized in the browser and saved with the chat; it can reuse the latest image on a relevant follow-up. No Firebase Storage subscription is needed.

An inactive legacy GLM route targets Mistral; it has not been verified to work on this account. Only after verifying model access with a real request, set the server-only `GENERAL_AI_PROVIDER` to `mistral` and configure its private `MISTRAL_API_KEY`. This selects `zai-glm-5-3` with maximum reasoning and a 4,096-token total completion cap. Only final text chunks are displayed and saved; provider thinking chunks never become chat answers. The client allows up to two minutes for a reasoning response. A missing key or provider error fails explicitly; it never silently substitutes another model. Keep Mistral API pay-as-you-go disabled. The account dashboard showed $10/month included API usage and listed GLM rate limits, but the real GLM request returned HTTP 403, "This model is not available in your subscription tier." Its authenticated model catalog also contained no GLM models. Rate-limit listings do not prove model access. GLM remains inactive until an eligible, zero-cost hosting arrangement is verified.

The deployed public URL is `https://nimbus-ai.nimbusdo-sidhvik-ai.workers.dev`. This URL is safe to put in browser configuration. **Never put a Groq key in a `VITE_*` variable.**

## Setup and deployment

Use the official Wrangler CLI, authorize Worker deployment, and deploy with this directory's `wrangler.jsonc`. Configure the key with `wrangler secret put GROQ_API_KEY`; enter it privately when prompted. Never paste a key into chat, commit it, or add it to frontend configuration. Alternatively, use an ignored `.dev.vars` locally and Wrangler's secret tooling to upload it without printing it.

The Worker accepts the production origin only. For local development, use Wrangler's local server and set `ALLOWED_ORIGIN` to the exact local Nimbus origin. Set the frontend's `VITE_NIMBUS_AI_URL` to that local endpoint. Production defaults to the Pages gateway `https://nimbus-ai-gateway.pages.dev`, which calls this Worker through its service binding, and can be overridden by that public environment variable.

A per-user limiter allows six requests per minute. General shares the connected Groq organization's free allowance; observed headers show 8,000 input tokens per minute. Three-pass answers consume more tokens than a single chat call. A short quota wait can be retried once, within an 85-second total deadline; larger or persistent limits fail with a clear message and retain the chat. Three light users can share the service but simultaneous long requests may wait or need a retry. No unlimited-availability claim is made. Nimbus never enables billing or automatically switches to a paid provider. Cloudflare AI and Mistral remain explicit, server-only alternatives; the default is Groq.

## Chats and sign-in

Both AI modes use a CORS-safelisted HTTPS POST (`text/plain` containing JSON) so managed browsers do not need an extra OPTIONS exchange. Its Firebase ID token travels in the request body, is verified exactly like the existing bearer header, and is removed before prompt construction. The token is not a provider API key and is never saved in chat data or forwarded to inference. Both official Firebase hostnames are allowed; other origins remain rejected. Both modes retry initial network failures through the existing second endpoint; HTTP errors and interrupted response streams do not resubmit. After both requests fail, public health probes without prompt or identity data distinguish `AI-POST` (a reachable endpoint but failed prompt request) from `AI-NETWORK` (neither health probe succeeded). This improves compatibility and diagnosis but cannot make an endpoint reachable if a school blocks its domain.

General chats, the assignment prompt, rubric, source evidence and small attached images are stored under `users/{uid}/aiChats/{chatId}` in Firestore. Existing rules restrict this path to the signed-in owner. Users can delete conversations, start new ones, and reopen saved ones. Only the last eight messages are sent to the model; incomplete assistant answers are excluded. Long conversations and requests are bounded to protect free allowances. A deleted Nimbus chat is removed from Firestore; deletion does not promise removal from provider logs.

Firebase uses local auth persistence. When a session is restored, visiting Nimbus's root redirects to My Day. Signing out, clearing browser storage, using a different browser, or private browsing can require a new login.

## Verification

From the repository root, run `pnpm --filter @workspace/api-server exec node --import tsx --test ../ai-worker/test/worker.test.mjs`. Worker tests cover actual Firebase JWT signatures, auth rejection, mode isolation, rate limiting, safe upstream failures, and structured responses. Frontend stream tests live in `artifacts/api-server/test/generalStream.test.mjs` alongside existing task tests. Browser verification exercises copying, saved chats, context, fullscreen, mobile layouts, and navigation. A real provider smoke test requires a configured Groq secret. Synthetic qualification cases and chart fixtures are in `eval/`; grading expectations are never sent to the model. Gemini and GLM evaluations must remain unrun until eligible zero-cost access is available. Local quality scores are not public benchmark points or proof of superiority over those untested models.

Simple task dates and project containers use the shared deterministic capture parser before a model request. Unnamed tasks retain an empty title, displayed as “Untitled task” in the preview. Next week means seven days after the supplied local date, and next Monday is the next future Monday. Project confirmation saves each task with its project ID and subject.

Date parsing accepts common scheduling typos and short forms, including `tmrw`, `tmr`, `tomorow`, `tommorrow`, `yday`, `tdy`, `next mon`, `next wk`, and `Octomber 21`. Correction applies only to the parser's view of dates. Original task titles and checklist text stay intact; quoted names, project/subject tags, and ordinary words such as `SAT` and `sun` are protected. Both My Day quick capture and Task AI share this parser.
